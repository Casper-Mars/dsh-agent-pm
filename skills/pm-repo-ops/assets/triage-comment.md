# Triage 评论模板

```text
结论：<接受 / 暂缓 / 需要补充 / 重复 / 不做>

依据：<证据等级 + 具体事实 + 来源>

下一步：<负责人 + 动作 + 检查点，不写工期>

未决：<缺什么、谁补、何时复核>
```

## 示例（接受）

```text
结论：接受

依据：E3 三位独立用户描述了同一导出失败场景（#12、#18、#24），可在 2026-11-10 版本复现。

下一步：@cto 评估实现路径；进入下个 milestone；AC 见 #30。

未决：是否需要兼容旧导出格式，@pm 在 11-15 前确认。
```

## 示例（需要补充）

```text
结论：需要补充

依据：目前只有一句「导出很慢」，缺少数据量、文件类型与耗时。

下一步：请补充 1) 数据量 2) 导出格式 3) 实际耗时与期望耗时 4) 复现步骤。

未决：14 天内无回应将关闭；补充后重新 triage。
```

## 示例（不做）

```text
结论：不做

依据：该能力需要私有化部署，与当前 SaaS 路线冲突；已有 2 个替代方案。

下一步：记录到需求池；如出现 3 个以上企业客户且愿意付费，重新评估。

未决：@pm 每季度复核一次。
```
