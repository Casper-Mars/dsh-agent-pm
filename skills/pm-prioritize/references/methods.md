# 排序方法

## 方法选择

| 场景 | 方法 | 说明 |
|---|---|---|
| 条目多、需要快速筛 | ICE | Impact / Confidence / Ease，适合粗排 |
| 有较可靠的成本与覆盖面 | RICE | Reach × Impact × Confidence ÷ Effort |
| 需要理解用户满意度分布 | Kano | 基本型 / 期望型 / 兴奋型 / 无差异 |
| 延迟有明确代价 | Cost of Delay | 推迟一周损失多少 |
| 范围必须硬砍 | MoSCoW | Must / Should / Could / Won't |
| 时间盒固定 | Appetite | 先定愿意投入的时间，再定范围 |

## 使用纪律

- 分数是沟通工具，不是真理；每行必须能口头解释。
- Reach 用真实触达人数或比例，不拍脑袋。
- Effort 用相对大小（S/M/L），不写人日。
- Confidence 低时，先做假设测试，不硬排。
- 方法一旦选定，全表统一，不混用。

## Kano 的用法

- 基本型缺失会导致强烈不满，必须补齐。
- 期望型越多越好，但边际收益递减。
- 兴奋型能带来口碑，但不稳定。
- 无差异型直接砍，不做。

## 反模式

- 用分数替代判断。
- 先有结论再凑分数。
- 只算价值不算成本与风险。
- 把 Kano 当问卷结果，不做样本控制。
