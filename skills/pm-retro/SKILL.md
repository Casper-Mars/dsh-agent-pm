# 复盘与学习

复盘不是总结会，是更新判断：哪些假设成立、哪些错了、下一步改什么。

## Iron Law

> 没有数据，不做复盘。

## 什么时候用 / 不用

- 用：版本上线后、实验结束、重大事故后、季度回顾。
- 不用：日常同步、追责会、没有数据的「感觉复盘」。

## 流程

1. **拿数据**：目标、基线、实际值、样本量、观察窗口；缺数据先补，不猜。
2. **对比目标**：逐条目标判定达成 / 未达成 / 无法判断。
3. **验证假设**：按 `references/assumption-review.md` 逐条判定，不合并。
4. **看意外**：哪些结果与预期不同，可能原因是什么。
5. **写结论**：支持 / 不支持 / 无结论；不把相关性写成因果。
6. **回填**：更新机会树与需求池，见 `references/opportunity-backfill.md`。
7. **定下一步**：扩大 / 迭代 / 回滚 / 放弃，写负责人与检查点。
8. **记录格式**：按 `references/retro-format.md` 输出，结论进 `assets/retro-summary.md`。

## 门禁

| # | 门禁 | 通过线 | 不过怎么办 |
|---|---|---|---|
| 1 | 有数据 | 目标、基线、实际、样本量 | 补数据或标「无法判断」 |
| 2 | 逐条目标 | 每个目标有判定 | 不合并 |
| 3 | 逐条假设 | 每个假设有判定与证据 | 不合并 |
| 4 | 结论分级 | 支持 / 不支持 / 无结论 | 重写 |
| 5 | 有回填 | 机会树 / 需求池已更新 | 补 |
| 6 | 有下一步 | 动作 + 负责人 + 检查点 | 补 |

## 输出契约

复盘摘要五段：目标 vs 结果、假设判定、意外发现、结论、下一步。模板见 `assets/retro-summary.md`。

## 反合理化

| 借口 | 现实 |
|---|---|
| 数据不好看，先不写 | 坏结果才是复盘的价值 |
| 大概是因为…… | 没有证据就是猜测，写「未知」 |
| 整体不错 | 「不错」不是结论，给指标 |
| 复盘就是找责任人 | 复盘是更新判断，不是追责 |
| 下次注意 | 「注意」不是动作，写具体改变 |

## 红旗

- 用叙事替代数据。
- 只复盘成功，不复盘失败。
- 假设判定含糊（「部分成立」但没有边界）。
- 结论没有回填到机会树。
- 下一步没有负责人。
