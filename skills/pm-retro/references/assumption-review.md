# 假设验证

## 逐条判定

| 假设 | 验证方式 | 证据 | 判定 |
|---|---|---|---|
| 用户愿意改变现有流程 | 访谈 / 行为数据 |  | 成立 / 不成立 / 无结论 |
| 用户能自己完成 | 可用性测试 |  |  |
| 技术可支撑 | 预研 / 压测 |  |  |
| 商业上可接受 | 成本 / 合规确认 |  |  |

## 规则

- 一次只判一条，不合并。
- 「部分成立」必须写清边界：对谁成立、在什么条件下成立。
- 无结论要写缺什么证据，不硬判。
- 假设错了要更新机会树，不只改文档。

## 常见错误

- 用整体指标好看来证明单个假设成立。
- 事后挑一个支持结论的指标。
- 把用户「说会使用」当成「真的使用」。
- 假设没写清就开始验证。
