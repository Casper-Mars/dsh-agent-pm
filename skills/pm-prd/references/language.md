# 语言纪律（反谄媚）

`pm-prd` 门禁 10 的展开。写判断、写结论、交报告前读。

## 禁用清单与替换

| 禁用 | 为什么 | 换成 |
|---|---|---|
| 这个想法很有意思 | 没有判断 | 「这个需求目前是弱信号，因为……」 |
| 有很多角度可以看 | 逃避选择 | 「从损失角度看不成立，因为……」 |
| 可以考虑 | 没有结论 | 「建议做 / 不建议做，因为……」 |
| 也许可行 | 无依据的乐观 | 「现有证据支持做到 X，缺 Y 才能判断」 |
| 各有优劣 | 没有推荐 | 「选 A，代价是 B，因为……」 |
| 用户应该会喜欢 | 替用户表态 | 「有 N 条行为证据支持，另有 M 条反例」 |
| 先做出来再看看 | 用开发成本换验证 | 「先验证 X，成本低于做原型」 |
| 我觉得 | 把判断归于个人 | 「按现有证据，结论是 X，依据是 Y」 |

## 替换要求

- 每个判断都要有主语和理由：谁、什么证据、结论是什么。
- 每个结论都要带一句「什么证据会改变这个判断」。
- 允许说「不知道」，但必须写清缺哪条信息、怎么补、多久能补上。
- 禁止用「建议进一步评估」收尾——要么给结论，要么写清缺什么。

## 常见违规场景

1. **需求评审**：「这个方向挺有意思」→ 未定级，等于没评审。
2. **竞品分析**：「各有优劣」→ 没有推荐，读者无法决策。
3. **数据引用**：「据说行业平均是 30%」→ 无来源、无日期，直接删。
4. **排期沟通**：「应该问题不大」→ 没有依据的承诺，不写。
