# 需求诊断：五问、证据分级、信号分级与 kill 条件

`pm-prd` 门禁 1 的展开。诊断没定级，不进第 2 章。

## 一、五问（一次问全，不挤牙膏）

| # | 问题 | 好答案 | 不合格 |
|---|---|---|---|
| Q1 谁 | 具体是谁？能说出一个真实的人或可识别角色？他负责什么？ | 角色 + 职责 + 可核对来源（某公司运维负责人，每周 3 次告警风暴） | 企业客户 / 中小企业 / 所有人 |
| Q2 场景 | 上一次遇到是什么时候？当时在做什么？卡在哪一步？ | 时间点 + 操作序列 + 卡点 | 经常遇到 / 大家都有 |
| Q3 现在怎么凑合 | 现在用什么办法？手工表格、聊天工具、脚本，还是干脆不解决？ | 具体工具与动作，以及为什么不好用 | 没有解决方案 / 啥也没做 |
| Q4 损失多大 | 一次损失多少时间 / 钱 / 客户？一个月几次？ | 可换算量级（每次 2 小时，每周 3 次，占 15% 工时） | 影响效率 / 体验不好 |
| Q5 愿意付出什么 | 愿意付多少钱、换掉什么工具、走多远？ | 具体金额、迁移动作、时间承诺 | 应该会有人买 / 上线就知道了 |

追问原则：

- 答不上来记「未知」，不替对方补。
- 一次问全五问；分五次问会得到五次临时编造的答案。
- 出现形容词就追问数字；出现「大家」就追问具体的人。
- 同一个问题问三个不同的人，答案一致才算交叉验证。

## 二、证据分级

| 等级 | 长什么样 | 能支撑的结论 |
|---|---|---|
| E1 行为 | 已在用土办法解决、已付费、已为此改流程 | 强需求 |
| E2 付费 | 报价被接受、有预付款、采购已启动 | 强需求 |
| E3 原话 | 具体描述损失、替代方案与触发场景 | 中需求（需补行为证据） |
| E4 转述 | 销售 / 客服 / 老板转述「用户说想要」 | 只能当假设 |
| E5 表态 | 点赞、+1、同感、收藏、注册 | 只能当线索 |

结论的证据等级不能高于手上最低的那条关键证据。

## 三、信号分级

| 等级 | 判据 | 下一步 |
|---|---|---|
| 强 | E1 / E2 齐全，Q1–Q4 落到具体人和数 | 直接进 PRD |
| 中 | E3 充分，Q5 缺失或模糊，损失可换算但未验证付费 | 可进 PRD，第 9 章标未决；或先补 Q5 |
| 弱 | 只有 E4 / E5，场景或损失有一项说不清 | 不进 PRD；补证据或找下一批用户 |
| 伪 | 问题不存在、没人愿意付出、受益者不是付费者 | 不做，留复活条件 |

每级都要写「为什么定在这一级」和「什么证据会升级 / 降级」。

## 四、kill 条件（任一命中即「不做」）

1. 伪需求：Q3 答「现在啥也没做，也不觉得有问题」。
2. 现状无成本：Q4 损失小于解决成本。
3. 无人愿意付出：连续三个真实用户给不出金额、迁移动作或时间承诺。
4. 受益者不付费：用的人不掏钱，掏钱的人不用。
5. 不在射程内：所需能力、渠道或资质明显不具备。

kill 不是终点：写清「什么证据出现可以翻案」。

## 五、结论卡片

```text
问题陈述：<角色 + 场景 + 损失>
信号等级：强 / 中 / 弱 / 伪 —— 理由：<对应哪几条证据>
证据清单：E? <来源与日期>
缺失证据：<还差哪一项，怎么补>
证伪条件：<出现什么就说明判断错了>
建议下一步：做 / 不做 / 先补证据（补什么、找谁、多久）
```

## 六、反例

- 「很多用户都说想要」——只有 E4 / E5，没有行为证据。
- 「损失很大」——不可换算，等于没损失。
- 「先做出来再看看」——用开发成本换验证。
- 只给等级不给理由——评审无法反驳。
