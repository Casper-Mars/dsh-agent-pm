# 变更卡（`s`）

适用：用户可观察行为要改，范围在单模块内，不动对外契约，但需要写清做与不做。

## 模板

```markdown
## 问题
<现象 + 影响面，1–3 行；有证据链接就贴>

## 期望行为
<改完后用户能看到什么；异常情况怎么表现>

## 范围
- 做：<本期改什么>
- 不做：<最容易顺手扩散的那一项>

## 验收
1. <前置 + 动作 + 可观察结果>
2. <异常或边界的一条>

## 风险与依赖
- <依赖的模块 / 数据 / 人；没有写「无」>

级别：s
```

## 规则

- 全文 ≤600 字或 1 屏，超了说明该升到 `m`。
- 验收 2–5 条，一条只验一件事；不写「体验流畅」。
- 「不做」必须有且只有最容易被顺手加进来的那一项；凑不出的写「无」。
- 不写指标、分期、数据模型、技术方案。
