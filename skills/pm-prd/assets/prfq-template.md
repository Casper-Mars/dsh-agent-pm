# PR-FAQ 模板

> 先写新闻稿，再写 FAQ。目的不是营销，而是逼出「为谁、解决什么、凭什么」。

## 新闻稿（≤ 1 页）

```text
标题：<用户视角的一句话，不用内部代号>

<日期>，<公司> 发布 <产品/功能>，帮助 <目标用户> 在 <场景> 下 <完成什么>。

问题：<用户现在的处境与损失，带一个具体例子>
方案：<一句话说清做什么，不写技术>
用户的话：<引用真实访谈，注明来源；没有就写「待补充」>
如何开始：<获取方式 / 迁移路径 / 价格变化>
```

## 内部 FAQ

| 问题 | 回答要求 |
|---|---|
| 为谁做？ | 角色 + 规模 + 现有替代 |
| 不做会怎样？ | 损失量化或明确的风险 |
| 凭什么我们能做？ | 能力、渠道、数据或成本优势 |
| 怎么衡量成功？ | 指标、基线、目标、窗口 |
| 最大的风险是什么？ | 价值/可用/可行/商业可行各一条 |
| 什么情况下放弃？ | 证伪条件与检查点 |
| 不做什么？ | 至少三条非目标 |

## 外部 FAQ

- 价格会不会变？
- 老用户要不要迁移？
- 数据与隐私怎么处理？
- 出问题怎么回滚？

写不出来，说明需求还没想清，不要进入开发。
