# 机会解决方案树（OST）

## 结构

```text
期望结果（产品指标，不是收入）
├─ 机会 A（用户需求 / 痛点 / 欲望）
│  ├─ 方案 A1 ── 假设测试
│  └─ 方案 A2 ── 假设测试
└─ 机会 B
   └─ 方案 B1
```

## 规则

1. 顶层是**产品结果**：用户行为的变化，例如「新用户 7 日内完成首次交付」。
2. 机会用需求语言写：「需要确认改动会不会影响老客户」，不写「要一个对比视图」。
3. 一个机会至少配两个方案，避免第一个想法锚定。
4. 每个方案列出假设，按「错了代价最大」排序，先测最危险的。
5. 每 3–4 次访谈刷新一次树；树是决策记录，不是海报。
6. 被 kill 的机会保留，写翻案条件。

## 假设类型

| 类型 | 问法 | 最小验证 |
|---|---|---|
| 价值 | 用户真的愿意为解决它改变行为吗 | 访谈故事、预售、落地页 |
| 可用 | 用户能自己完成吗 | 原型可用性测试 |
| 可行 | 我们做得出来吗 | CTO 技术预研 |
| 商业可行 | 公司能支持吗（成本 / 合规 / 渠道） | 财务、法务、销售确认 |
| 伦理 | 会不会伤害某类用户 | 数据审计、边界案例 |
