# 故事切片

## 原则

- 纵向切片：每一片都从用户入口到结果，能独立上线、独立验收。
- 不按技术层切（前端 / 后端 / 数据库），那会得到「都做完了才能用」。
- 第一片优先覆盖主路径的最小闭环。
- 每片写清：谁、在什么场景、完成什么、怎么验。

## 切片顺序

1. 主路径 + 最小数据
2. 异常路径（空、超时、无权限、重复）
3. 边界与规模
4. 体验优化
5. 非功能需求（性能、审计、合规）

## 检查

- 这一片能否单独发布而不伤害用户？
- 这一片能否单独验收？
- 如果只做这一片，用户能得到什么？
- 切片之间是否有隐藏依赖？

## 反模式

- 按「数据库 / API / UI」切。
- 第一片是「搭框架」，用户看不到任何东西。
- 切片大到无法在一周内验收。
- 切片之间共享未完成的分支。
